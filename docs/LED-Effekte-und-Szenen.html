1 · Überblick

Bisher waren die meisten Effekte Matrix-Effekte für ein 22×23-Raster. Auf der Gitarre liegen die LEDs aber als eine geschlossene Kette von 163 LEDs rund um die Kontur. Nachbarn im Raster sind dort oft nicht nebeneinander, deshalb sieht vieles wie Rauschen aus. Die neuen Bausteine nutzen die echte Form:

BausteinWas er machtDatei
Kontur-Effekte11 Effekte, die entlang der Kontur, in Zonen (Kopf, Hals, Hörner, Korpus) oder im echten Raum (XY) rechnen.guitarShapeFX.cpp/.h
Gurt-OverrideDer Gurt kann ein eigenes Bild bekommen, statt nur eine Kopie der Gitarre zu zeigen.guitarShapeFX, markerLEDs.cpp
FarbschemataLegen fest, aus welchen Farben alle Programme ihre „Zufallsfarben“ ziehen. Ohne Schema bleibt alles wie bisher.colorSchemes.cpp/.h
SzenenEin Part sagt nur was passieren soll (SCENE_DROP). Jedes Gerät zeigt dazu sein passendes Programm, ohne #ifdef im Song.scenes.cpp/.h
Die Szenen-Features liegen auf dem Branch szenen, der auf neueEffekte aufbaut. Wer szenen auscheckt, hat alles.

2 · Kontur-Konzept & Kalibrierung

Alle Kontur-Effekte rechnen mit der Konturposition k: k = 0 ist die Spitze der Kopfplatte, dann geht es einmal um die Gitarre herum (Kopfplatte unten → Hals-Unterkante → unteres Horn → Korpus → oberes Horn → Hals-Oberkante → Kopfplatte oben). Symmetrische Effekte nutzen den Abstand d von der Kopfspitze: d = 0 ist der Kopf, d = 81 (anz_LEDs/2) liegt unten am Korpus.

Für räumliche Effekte hat jede LED zusätzlich XY-Koordinaten. Sie werden beim ersten Effekt einmal aus einem Umriss berechnet, der vom Foto der Gitarre abgezeichnet wurde (initGuitarShape()). Weil die LEDs gleichmäßig auf dem Strip sitzen, werden sie gleichmäßig auf diesem Umriss verteilt.

3 · Die 11 Kontur-Effekte

Alle Effekte folgen dem bekannten Muster progXxx(durationMillis, nextPart, …). Sie setzen beim ersten Aufruf Dauer und nächsten Part, arbeiten mit dem 2-ms-Timer statt delay(), respektieren LEDsTurnedOff und rufen am Ende gitBlindingLEDs_OFF_MarkerLEDs_ON() + FastLED.show() auf. Die Fret-Marker bleiben also sichtbar.

4 · Gurt-Override

Der Gurt-Strip hängt an DATA_PIN_2 und zeigt normalerweise eine Kopie von leds[] ohne Marker. gitBlindingLEDs_OFF_MarkerLEDs_ON() macht dazu memcpy(leds2, leds, …). Für Effekte, die Gurt und Gitarre unterschiedlich bespielen, gibt es:

SymbolBedeutung
bool strapOverrideIst es true, wird ledsStrap[] statt der Kopie auf den Gurt gegeben. Die restlichen LEDs von leds2 werden schwarz.
CRGB ledsStrap[anz_LEDs_STRAP]Eigener Puffer für den Gurt.
ResetswitchToPart() setzt strapOverride bei jedem Part-Wechsel auf false. Ein Effekt muss es deshalb in jedem Frame neu setzen, so wie progFuse.

Bisher nutzt nur #11 Zündschnur den Override. Alle anderen Effekte lassen den Gurt wie gewohnt mitlaufen.

5 · Farbschemata

Viele Programme würfeln ihre Farben selbst. Bisher ließ sich deshalb nicht gezielt steuern, welche Farben zu sehen sind. Ein Farbschema legt fest, aus welchen Farben alle Programme ihre Zufallsfarben ziehen. Das gilt für die alten Programme genauso wie für die neuen.

Verwendung

void MeinSong() {
    setColorScheme(SCHEME_FIRE);                  // VOR dem switch: gilt für alle Parts
    switch (prog) {
    case 20: progFullColors(8000, 30, 500);  break;   // wechselt nur noch zwischen rot/orange/gelb
    case 30: setColorScheme(SCHEME_ICE);          // nur für diesen Part
             progStrobo(1630, 35, 75, getRandomCRGB()); break;
    case 35: progPalette(8000, PALETTE_SCHEME, 40); break;  // Verlauf aus den Schemafarben
    …
Warum oben in der Song-Funktion? Die Song-Funktion läuft bei jedem 2-ms-Takt, der Aufruf kostet praktisch nichts. So stimmt das Schema auch dann, wenn ein Client per BLE mitten im Song einsteigt und Part 0 nie gesehen hat. switchToPart() setzt das Schema bei jedem Part-Wechsel auf SCHEME_RANDOM zurück. Songs ohne Schema verhalten sich deshalb exakt wie bisher.

6 · Szenen

Bisher zeigen die Geräte meist dasselbe Programm. Wer pro Gerät etwas anderes wollte, brauchte #ifdef in jedem Part. Szenen drehen das um: Der Song sagt, was passieren soll, und jedes Gerät entscheidet zentral in scenes.cpp, wie es das umsetzt.

void MeinSong() {
    setColorScheme(SCHEME_NEON);
    switch (prog) {
    case 0:  scene(SCENE_CALM,     15000,  5, 128); break;
    case 5:  scene(SCENE_VERSE,    30000, 10, 128); break;
    case 10: scene(SCENE_BUILDUP,   7500, 15, 128); break;   // 4 Takte Aufladen, Explosion am Ende
    case 15: scene(SCENE_DROP,     15000, 20, 128); break;
    case 20: progStrobo(1875, 25, 75, getRandomCRGB()); break;   // normale Programme gehen weiterhin
    …
Wichtig: Alle Geräte rufen die Szene mit derselben Dauer auf, sonst laufen die Parts auseinander. Beats werden ab Part-Start aus millisCounterForProgChange berechnet, und der Part-Start wird per BLE synchronisiert. bpm = 0 heißt 120.

Eigene Szenen ergänzen

  1. Neue ID in enum SceneID (scenes.h) anlegen.
  2. In scene() (scenes.cpp) je einen case pro DEVICE_CLASS-Block ergänzen. Gilt die Szene für alle Geräte gleich, reicht ein case im oberen switch, der mit return endet.
  3. Alle Geräte mit dem neuen Stand flashen, denn die Zuordnung ist in jede Firmware kompiliert.

7 · Primitive für alle Geräte

Diese Programme schreiben direkt in leds[0..anz_LEDs) und laufen deshalb auf jedem Gerät. Die Szenen nutzen sie, sie funktionieren aber auch einzeln in normalen Songs.

SignaturWirkung
progBreathe(dur, next, CRGB col, periodMillis, maxVal)Ganzes Gerät atmet in col, Helligkeit per quadwave8 zwischen 3 und maxVal.
progBeatFlash(dur, next, bpm, CRGB col, delayMillis)Flash auf jedem Beat (+ Verzögerung), klingt über max. 70 % des Beats bzw. 450 ms quadratisch ab.
progPingPong(dur, next, bpm)Gemeinsame Folge über sharedRand8: Pro Beat ist genau eine Bühnenposition aktiv und flasht in deviceColor(). Der Rest ist dunkel.
progLampFill(dur, next, CRGB col)Lampe füllt sich über Dauer − 600 ms von unten, mit heller Kante und leichtem Flackern. Danach 600 ms weiße Explosion, synchron zu progChargeBlast in SCENE_BUILDUP.
progLampPulse(dur, next, bpm, CRGB col)Auf jedem Beat ein leichter Flash, dazu ein Lichtschuss mit 6-LED-Schweif, der nach 60 % des Beats oben ankommt.
progLampFire(dur, next, bool blueFire)1D-Fire2012 von unten nach oben (nutzt fire2012Step).
uint8_t sharedRand8(uint32_t salt)Hash aus songID, prog und salt, ohne Zustand. Gleicher „Zufall“ auf allen Geräten. Bewusst nicht über randomSeed(), weil random() auf jedem Gerät unterschiedlich oft aufgerufen wird.

Lampen-Ausrichtung: LAMP_IDX0_AT_BOTTOM (1 = LED 0 unten). Füllt sich eine Lampe von oben, auf 0 setzen.
