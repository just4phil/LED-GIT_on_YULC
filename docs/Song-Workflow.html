Song-Workflow: vom Excel zur LED-Show

Neue Songs werden nicht mehr von Hand in songs.cpp programmiert: Du pflegst pro Song eine einzige Excel-Tabelle (Takte, Änderungswunsch, Energie), Claude gestaltet daraus die Show, der Generator erzeugt den C++-Code. Jeder Song hat einen eigenen Ordner, jede Generierung wird als Version gesichert. Stand 06.10.2026.

1 · Überblick

Ein Song läuft ab dem Start-MIDI-Signal (CC 22 = Song-ID, Kanal 10) millisekundengenau durch. Alle Part-Dauern ergeben sich deshalb aus Tempo × Takten. Du trägst nur die Taktnummern ein, die Millisekunden rechnet der Generator.

DateiWerInhalt
quelle/struktur.xlsxduDie einzige Datei, die du pflegst: Song-ID, BPM, StartBit und pro Part Taktnummer, Name, Änderungswunsch, Energie. Das Werkzeug schreibt dort nur die Spalte „Effekt (füllt KI)“ – alles andere bleibt, wie du es eingetragen hast.
show.yamlClaudeWie es aussieht: Szene, Farbschema, Geräte-Overrides, Akzente je Part (per Part-Name, ohne Takte)

Ein Ordner pro Song

songs/AllTheThingsSheSaid_v1/
  quelle/struktur.xlsx ← DEINE Datei: Takte, Änderungswünsche, Energie
  show.yaml            ← aktive Show, von Claude abgeleitet
  generated.cpp        ← aktiver Code dieses Songs
  versionen/
    2026-10-06_1116/   ← struktur.xlsx, show.yaml, generated.cpp, info.yaml

Das _v1 im Ordnernamen steht für die Fassung des Songs (Arrangement, Audio). Eine neue Fassung bekommt einen eigenen Ordner …_v2 und eine eigene Song-ID. Die Versionen der Show liegen darunter in versionen/.

In den Befehlen genügt der Anfang des Ordnernamens, Groß- und Kleinschreibung ist egal: songgen.py allthe.

Weggefallen (06.10.2026): die Zwischendatei song.yaml, die Audio-Analyse der MP3 und der Import aus Chord-Sheets. Liegen in einem Ordner noch song.yaml, audio-analyse/, eine MP3 oder quelle/excel-kalkulation.csv, liest sie kein Werkzeug mehr – du kannst sie löschen.

2 · Einmalige Einrichtung

Die Werkzeuge brauchen Python mit zwei Paketen. Einmal pro Rechner, in Git Bash im Projektordner:

python -m pip install -r tools/requirements.txt     # pyyaml, openpyxl

Getestet mit Python 3.9. Die frühere Umgebung tools/.venv mit den Audio-Bibliotheken wird nicht mehr gebraucht.

3 · Neuer Song Schritt für Schritt

Beispiel: „Vogue“ im Ordner Vogue_v1. In den Befehlen genügt danach der Anfang des Ordnernamens (vogue).

  1. Ordner und Tabelle anlegensonggen
    python tools/songgen.py Vogue_v1 --neu
    Legt songs/Vogue_v1/quelle/struktur.xlsx an, als Kopie der Vorlage songs/struktur-vorlage.xlsx (eine vorhandene Tabelle wird nie überschrieben). Du kannst die Vorlage oder die Tabelle eines anderen Songs auch von Hand dorthin kopieren. Name des Ordners: Songtitel ohne Leerzeichen plus _v1.
  2. Tabelle ausfüllendu
    In Excel: Titel, Interpret, Midi-StartNummer (= Song-ID, 1 bis 127), BPM, StartBit und pro Part eine Zeile mit von takt, Songpart, Änderungswunsch und Energie 0–5 (die Spalte „Effekt (füllt KI)“ bleibt leer, sie füllt das Werkzeug). Die letzte Zeile heißt „Ende“. Alle Felder in Abschnitt 4. Speichern nicht vergessen.
    • Ganz neuer Song: eine freie ID nehmen (python tools/songgen.py zeigt die vergebenen).
    • Neue Fassung eines alten, handgeschriebenen Songs: dieselbe ID wie bisher. Der Generator ersetzt dann den alten Aufruf, siehe Abschnitt 7, „Einen handgeschriebenen Song ersetzen“.
  3. Show gestalten und generierenClaude
    In Claude Code: „Gestalte die Show für Vogue_v1“. Claude liest die Tabelle, schreibt show.yaml, generiert den Code und baut die Firmware. Du bekommst die Timeline (Start und Dauer jedes Parts) und eine kurze Beschreibung der Dramaturgie.
    Ohne Claude geht es auch: show.yaml von Hand schreiben (Abschnitt 5) oder ganz weglassen – dann nimmt der Generator für jeden Part die Standard-Szene seiner Energie (0 Black, 1 Calm, 2 Verse, 3 Buildup, 4–5 Drop). Vorschau und Generieren: 
    python tools/songgen.py vogue --dry-run             # Timeline, Hinweise, Fehler - schreibt nichts
python tools/songgen.py vogue --note "erste Fassung"   # Code + Version
  4. Bauen und flashenPlatformIOdu
    pio run -e andresgit -e rinasbass -e lampe1 -e lampe2 -e scrollmatrix
    Per USB, ein Gerät nach dem anderen: 
    pio run -e andresgit    -t upload --upload-port COM3
pio run -e rinasbass    -t upload --upload-port COM8
pio run -e lampe1       -t upload --upload-port COM11
pio run -e lampe2       -t upload --upload-port COM10
pio run -e scrollmatrix -t upload --upload-port COM9
    Oder alle Geräte per WLAN, siehe docs/OTA-Update.html.
  5. Testendu
    Song per MIDI starten: CC 22 mit Wert = Song-ID auf Kanal 10. Prüfen:
    • Kommt der erste Part-Wechsel zu früh oder zu spät? Dann StartBit anpassen.
    • Läuft die Show langsam auseinander? Dann BPM prüfen.
    • Sitzt ein einzelner Wechsel falsch? Dann das von takt dieses Parts korrigieren.
  6. Nachsteuern – immer im Exceldu Claude
    • Timing (Takte, BPM, StartBit, Energie): in der Tabelle ändern, speichern, neu generieren (python tools/songgen.py vogue) – dafür braucht es keine neue Gestaltung.
    • Gefällt ein Part nicht: den Wunsch in die Spalte „Änderungswunsch“ schreiben („zu statisch, mehr Bewegung“), speichern, Excel schließen und Claude sagen „ich habe das Excel von Vogue geändert“. Oder Claude den Wunsch direkt im Chat nennen. Nach der Generierung steht in der Spalte „Effekt (füllt KI)“, was jetzt umgesetzt ist; den erledigten Wunsch löschst du selbst.
    • Part eingefügt, gelöscht oder umbenannt: Claude Bescheid geben, die Show muss dann nachgezogen werden. Der Generator bricht sonst mit einer Liste ab, welche Parts nicht mehr zur Show passen.
    Jede Generierung wird als Version gesichert, samt deiner Tabelle.
  7. Zurück zu einer älteren Fassungdu
    python tools/songgen.py vogue --versions
python tools/songgen.py vogue --restore 2026-10-06_1116
    Holt Tabelle, Show und Code dieser Version zurück. Details in Abschnitt 7.
  8. In Git sicherndu
    git add songs/Vogue_v1 src/songs_generated.cpp src/songs_generated.h src/main.cpp
git commit -m "Song Vogue"

4 · Die Tabelle struktur.xlsx (gehört dir)

Ein Song pro Datei, gelesen wird das Blatt „Struktur“. Das Werkzeug erkennt Kopf und Spalten an ihrer Beschriftung, nicht an der Position – du kannst also Spalten ergänzen, verschieben oder weitere Blätter anlegen. Beispiel (All The Things She Said):

Feld im KopfPflichtBedeutung
Titel, Interpret (Zeile 1)Titel jaDer erste Text ist der Titel, der Text daneben der Interpret. Daraus wird der Lauftext „Titel by Interpret“.
Midi-StartNummerjaDie Song-ID, 1..127: der MIDI-Wert von CC 22, mit dem der Song gestartet wird.
BPMjaTempo des Songs.
StartBitnein (0)Wie weit das Start-MIDI hinter dem Anfang der ersten Zeile kommt, als Bruchteil des Takts: 0,125 = 1/8, 0,25 = 1/4, 0,375 = 3/8. Der erste Part wird um diesen Betrag kürzer.

Ein Wert steht immer rechts neben seiner Beschriftung.

Spalte pro PartPflichtBedeutung
von taktjaTaktnummer, an der der Part beginnt. Die Taktnummern aus dem DAW (Cakewalk zählt ab 1; alle Tabellen und die Vorlage beginnen seit 08.10.2026 bei 1) – es zählt nur der Abstand zur ersten Zeile, eine Tabelle ab 0 funktioniert genauso. Halbe Takte als Kommazahl: 21,75 = drei Viertel nach Takt 21. Ein Part endet, wo der nächste beginnt.
SongpartjaName. Kommt er mehrfach vor, zählt das Werkzeug mit: chorus 1, chorus 1 (2), chorus 1 (3). Unter diesen Namen steht der Part in der Show.
Effekt (füllt KI)neinSchreibt das Werkzeug bei jeder Generierung: der Effekt, der für diesen Part gerade umgesetzt ist – erst der Aufruf bzw. die Szene mit Farbschema, dann Text, Ebene und Blinder, zuletzt eine Beschreibung in Worten. Hier nichts eintragen, es wird überschrieben.
ÄnderungswunschneinDein Wunsch in freien Worten („weißer Strobo auf den Auftakt“, „zu statisch“). Er gilt: Claude setzt ihn in der Show um. Kein Werkzeug ändert diese Spalte – ist der Wunsch erledigt, löschst du ihn selbst.
Neuer Vorschlag (KI)neinSchreibt das Werkzeug nur mit songgen.py <Song> --vorschlag (seit 10.10.2026): Ideen von Claude, wie der Part umgestaltet werden könnte – neue Szene, Farbwanderung, Blinder mit Taktnummer. Leer = der alte Effekt kann bleiben. Die Spalte ist nur zum Lesen und ändert nichts am Song: umgesetzt wird erst, was du in „Änderungswunsch“ einträgst (übernehmen, kürzen oder umformulieren). Du kannst sie jederzeit löschen.
Energie 0-5neinDeine Einschätzung des Parts, 0 = schwarz, 5 = Höhepunkt. Grundlage der Szenenwahl.
BPM pro PartneinTempo dieses Parts. Leer oder gleich dem BPM im Kopf = Songtempo (in der Vorlage leer, in älteren Tabellen eine Formel auf das BPM im Kopf). Nur bei einem Tempowechsel eintragen.
Beschreibung, AkkordeneinOptional: was musikalisch passiert, welche Akkorde klingen. Nur Information für die Gestaltung.
bisher (alter Code)neinBei den alten Songs: der Effekt, den der handgeschriebene Code an dieser Stelle auf der Gitarre zeigt (! = Hinweis, wo alter Code und alte Kalkulation voneinander abweichen). Nur zur Orientierung.

Zwischenzeilen: Wünsche auf den Vierteltakt genau

Zwischen zwei Parts dürfen beliebig viele Zwischenzeilen stehen: Zeilen mit „von takt“, aber ohne Songpart. Eine Zwischenzeile gehört zum Part darüber. So kann die Tabelle eine Zeile je Vierteltakt haben (0 / 0,25 / 0,5 / 0,75 / 1 …), und dein Wunsch steht genau an der Stelle, für die er gilt:

von taktSongpartEffekt (füllt KI)ÄnderungswunschBedeutung
20chorus 1SCENE_DROP, Farben SCHEME_SUNSET …Part-Zeile wie bisher
20,25leer: der Effekt des Parts läuft einfach weiter
21,75Blinder auf den Schlag, nur Lampenhier BlinderWunsch genau an dieser Stelle; links daneben trägt der Generator ein, was dort umgesetzt ist
23chorus 1b…ab hier Strobomit Songpart: keine Zwischenzeile mehr, sondern ein neuer Part, der hier beginnt
  • Leere Zwischenzeilen zählen nicht: eine nur gerasterte Tabelle gilt als unverändert, der Song muss nicht neu generiert werden.
  • Beide Formen gelten. Du kannst das volle Raster nehmen oder eine kompakte Tabelle behalten und nur dort eine Zwischenzeile einfügen, wo du einen Wunsch hast (z. B. eine Zeile mit „von takt“ 63,75).
  • Soll sich an einer Stelle der ganze Effekt ändern (andere Szene, andere Farben), gib der Zeile einen Songpart-Namen – dann beginnt dort ein neuer Part. Ein Wunsch in einer Zwischenzeile ist für Akzente gedacht, die über dem laufenden Effekt liegen (Blinder, Text, Ein- und Ausblenden).
  • Energie in einer Zwischenzeile wird gelesen und geprüft (0–5), hat aber noch keine Wirkung. BPM pro Part bleibt dort leer: ein Tempowechsel braucht einen eigenen Part.
  • „von takt“ sind Zahlen, keine Formeln (eine Formel wie =A6+0,25 verliert beim Zurückschreiben der Effekt-Spalte ihr Ergebnis; das Werkzeug schreibt die Spalte dann nicht).
  • Bestehende Tabelle rastern: python tools/songgen.py <Song> --raster legt quelle/struktur-raster.xlsx an – eine Kopie deiner Tabelle mit allen fehlenden Viertel-Zeilen. Deine Tabelle wird dabei nur gelesen. Die Zwischenzeilen sind in drei Ebenen eingeklappt, die Knöpfe oben links schalten die ganze Tabelle um: 1 = nur die Parts, 2 = dazu die vollen Takte, 3 = dazu die Viertel. Das Plus am linken Rand öffnet einen einzelnen Part oder Takt (Parts, in denen schon etwas steht, bleiben offen). Passt die Kopie, schließt du struktur.xlsx in Excel und ersetzt sie selbst durch die Kopie (umbenennen). Tabellen mit eigenen Formeln oder verbundenen Zellen rastert das Werkzeug nicht; dort fügst du die Zeilen in Excel ein.
  • Neue Songs: die Vorlage ist schon gerastert. Passen ihre Beispiel-Takte nicht zu deinem Song, lösche die Zwischenzeilen, trage die Parts ein und lass die Tabelle danach mit --raster neu rastern.
  • Erste Zeile ist immer die Pause am Anfang: Mit dem Start-MIDI sind alle Geräte schwarz, egal was dort als Änderungswunsch steht.
  • Letzte Zeile „Ende“ (auch „black“, „fini“): Ihr „von takt“ ist der Schlusstakt des Songs, sie ist kein eigener Part. Danach hängt der Generator Schwarz an – so lange, wie in ihrer Spalte „Effekt (füllt KI)“ oder „Änderungswunsch“ steht („10 sek.“; der Wunsch geht vor), ohne Angabe 10 Sekunden.
  • Weitere Spalten sind erlaubt und werden ignoriert, ebenso weitere Tabellenblätter (z. B. deine alte Kalkulation).
  • Speichern: Der Generator liest den zuletzt gespeicherten Stand. Die Datei darf in Excel geöffnet bleiben; nur für --restore muss sie geschlossen sein.
  • Millisekunden und Rundung übernimmt der Generator: er rechnet jede Part-Grenze aus der absoluten Zeit, dadurch entsteht keine Abweichung, die sich aufsummiert.
Deine Tabelle wird nie überschrieben. Claude darf sie nicht ändern (technisch gesperrt), der Generator liest sie nur. Einzige Ausnahme: --restore holt auf deinen Befehl die Tabelle einer älteren Version zurück und sichert vorher den aktuellen Stand.

5 · Die Show-Datei show.yaml (technisch)

function: gen_AllTheThingsSheSaid
scheme: SCHEME_ICE                  # Grundfarben
sections:
  intro:                            # = Songpart aus der Tabelle
    scene: SCENE_CALM
    scheme: SCHEME_ICE
    tail:                           # letzte 2 Beats als eigener Part
      beats: 2
      scene: SCENE_BUILDUP
    why: "leiser Chant, Crescendo in den Band-Einsatz"
  verse 1b:
    scene: SCENE_VERSE
    devices:                        # Ausnahmen für einzelne Geräte
      ANDRESGIT: "progSymmetricVU(${dur}, ${next}, ${bpm})"
  chorus:
    scene: SCENE_DROP
    text: "FUN"                      # Matrix zeigt Text, der Rest die Szene
  bridge hit:
    fx: "progStrobo(${dur}, ${next}, 75, CRGB::White)"

FeldStandardBedeutung
functiongen_<Name>Name der erzeugten C++-Funktion.
schemekeinsGrund-Farbschema für alle Parts ohne eigenes Schema.
scroll_texttruefalse schaltet den Lauftext am Songanfang ab.
scroll_title„Titel by Interpret“anderer Lauftext.
scroll_delay90Millisekunden pro Pixel, also die Laufgeschwindigkeit.

end_blinderkeinerEin Blinder klingt ins Schluss-Schwarz aus: end_blinder: 5 = beginnt mit dem Schluss-Schwarz voll hell und blendet 5 Sekunden lang aus (ausführlich {seconds: 5, amount: 100, color: warm, devices: [LAMPE1, LAMPE2]}). Gedacht als Fortsetzung eines Blinders, der im letzten Part bis zum Part-Ende voll steht, z. B. dort blinder: {at: 63, len: 2, hold: 1} = erst auf dem letzten Viertel eines 16-Takte-Parts (APT.).
sectionsZuordnung Part-Name → Gestaltung. Parts ohne Eintrag fallen auf energy zurück.

Felder pro Part

FeldBedeutung
sceneSzene für alle Geräte, jedes zeigt sie auf seine Art (siehe docs/LED-Effekte-und-Szenen.html):
Stimmung: SCENE_CALM (ruhiges Atmen), SCENE_VERSE (rhythmisch, dezent), SCENE_BUILDUP (lädt sich über den ganzen Part auf, Explosion am Ende), SCENE_DROP (volle Energie im Beat), SCENE_FIRE (Feuer auf allen Geräten)
Über die Bühne: SCENE_WAVE_LR, SCENE_WAVE_RL, SCENE_WAVE_OUT (Blitz pro Beat nach rechts, nach links, von der Mitte nach außen), SCENE_PINGPONG (pro Beat leuchtet genau ein Gerät, zufällige Folge), SCENE_CALL_RESPONSE (Frage/Antwort: linke und rechte Bühnenhälfte blitzen abwechselnd im Beat, die Matrix mit ihrer linken bzw. rechten Hälfte – jedes Gerät hat einen festen Puls)
Spotlight: SCENE_SOLO_GIT, SCENE_SOLO_BASS, SCENE_SOLO_DRUMS (Solist voll, Rest atmet dezent)
Bewährte Looks der alten Songs: SCENE_STAR (drehender Stern, der Refrain-Look), SCENE_SPARKLE (schnelle Einzelblitze, Höhepunkt), SCENE_GLOW (füllt sich langsam, wechselt gemeinsam die Farbe), SCENE_COLORS / SCENE_COLORS_WAVE (ganze Bühne eine Farbe pro Beat, stehend oder wandernd), SCENE_RAIN (fallende Leuchtspuren), SCENE_PALETTE (Farbband über die Bühne)
Bild auf der Matrix, die anderen pulsieren dazu: SCENE_DNA (DNA-Doppelhelix dreht sich in 2 Takten einmal; linke und rechte Bühnenhälfte pulsieren abwechselnd in den Strangfarben), SCENE_DNA_FLIP (stehende Helix, die Stränge tauschen jeden Takt die Seiten; alle Geräte pulsieren gemeinsam und sind im Moment des Tauschs dunkel), SCENE_DNA_FLIP_SCROLL (wie SCENE_DNA_FLIP, die Helix wandert dabei langsam quer über die Matrix)
Schluss: SCENE_FADEOUT (jedes Gerät blendet über die ganze Partdauer weich nach Schwarz aus; ab 2 Takten richtig sanft)
Effekte mit Zufallsfarben (auch SCENE_SPARKLE, SCENE_STAR) ziehen ihre Farben aus dem scheme des Parts. Für die freien Zufallsfarben der alten Songs SCHEME_RANDOM setzen.
fxBeliebiger Effektaufruf für alle Geräte statt einer Szene, z. B. "progStrobo(${dur}, ${next}, 75, CRGB::White)". Die Funktion muss in einem dieser Header stehen: FXprograms.h, fxBase.h, guitarShapeFX.h, scenes.h, matrixFunctions.h, functions.h, colorSchemes.h. Stehen scene und fx beide da, gilt fx.
schemeFarbschema: SCHEME_FIRE, SCHEME_ICE, SCHEME_NEON, SCHEME_ROYAL, SCHEME_TOXIC, SCHEME_SUNSET, SCHEME_RETRO, SCHEME_WHITE, SCHEME_RED, SCHEME_BLUE, SCHEME_RANDOM
fadeFarbwanderung: die Farben des Schemas laufen im Takt zu einem Ziel und wieder zurück, auf allen Geräten gleichzeitig. Funktioniert mit jeder Szene und jedem Effekt, der dem Schema folgt, und braucht ein scheme (nicht SCHEME_RANDOM).
fade: complement – zur Gegenfarbe und zurück, ein Takt pro Weg. Der Weg führt über den Farbkreis (Blau über Violett und Rot nach Orange), nicht durch Grau.
fade: {to: triad, per: 8} – to: complement (Gegenfarbe), triad (ein Drittel Farbkreis), analog (Nachbarfarbe, dezent), rainbow (läuft immer weiter um den Farbkreis) oder ein zweites Schema wie SCHEME_NEON.
per: Dauer eines Wegs – beat, half (2 Beats), bar (Standard) oder eine Zahl in Beats, z. B. 8 für 2 Takte. Bei rainbow die Zeit von einer Farbe zur nächsten.
hard: true – springt im Takt zwischen den beiden Farben, statt weich überzublenden.
Weiß bleibt weiß. Ein tail übernimmt die Farbwanderung nicht, er kann ein eigenes fade haben.
devicesAusnahmen als Effektaufruf je Schlüssel. Geräteklassen: guitar, lamp, matrix. Einzelne Geräte: ANDRESGIT, RINASBASS, LAMPE1, LAMPE2, SCROLLMATRIX, GITBOARD. Ein einzelnes Gerät hat Vorrang vor seiner Klasse. Geräte ohne Eintrag zeigen die Szene.
tailDie letzten N Beats als eigener Part (Strobo-Absprung, Aufladen vor dem Chorus). Felder: beats (Pflicht, kürzer als der Part) und scene oder fx, dazu wahlweise scheme, devices, why sowie Übergang und Modifikatoren (transition, pulse …). Ohne eigenes scheme gilt das des Parts. Pro Part ist nur ein tail möglich. Für mehr Akzente den Part in song.yaml teilen.
textText auf den Matrix-Geräten, alle anderen Geräte spielen ihre Szene weiter. Position, Tempo und Farbe ergeben sich von selbst:
text: "FUN" – ein Wort, zentriert, pulsiert im Beat.
text: "THEY JUST WANNA HAVE FUN" – mehrere Wörter, pro Beat das nächste, danach von vorn.
text: {words: "HAVE FUN", per: bar} – per: beat (Standard), half (2 Beats), bar (ein Takt) oder eine Zahl in Beats.
text: {words: "THIS IS NOT ENOUGH*5", per: beat} – ein Wort mit *Zahl am Ende bleibt so viele per stehen: THIS, IS, NOT je einen Beat, ENOUGH fünf (ab Schlag 4 bis zum Ende des nächsten Takts), dann von vorn.
text: {words: "FUCK_YOU", per: 32} – ein Unterstrich wird als Leerzeichen gezeichnet, trennt aber nicht: beide Wörter stehen zusammen als ein Bild auf der Matrix (zusammen höchstens 9 Zeichen).
text: {words: "…", flash: true} – die Wörter blitzen auf und klingen ab wie die Lampen im Beat-Blitz (über einer Szene scheint sie dabei durch); ohne flash gehen sie hart an und aus. Ein Wort mit *Zahl steht voll hell und klingt erst in seinem letzten per ab. Nur für words, sinnvoll mit per: beat.
text: {scroll: "I come home in the morning light"} – Lauftext, der genau am Part-Ende fertig ist (bei langen Parts mehrere Durchläufe).
Optional color: weiss, rot, blau, gruen, gelb, orange, pink, lila, cyan oder ein CRGB-Ausdruck; ohne Angabe die Farben des Schemas, bei jedem Wort die nächste. schwarz stanzt den Text aus (nur mit over: true): die Buchstaben-LEDs sind aus, die Szene leuchtet drumherum – lesbar nur über hellen, gleichmäßigen Flächen wie Farbband oder Glow.
Statt color ein Farbverlauf in der Schrift: text: {scroll: "…", gradient: scheme}. gradient: scheme (Verlauf aus den Farben des Schemas), rainbow, party, clouds, stripes (Regenbogen-Streifen mit harten Kanten), matrix (Grüntöne), random oder eine Paletten-ID von progPalette. Ausführlich: gradient: {palette: rainbow, dir: v, per: bar} – dir: h quer über die Matrix (Standard, die Buchstaben laufen durch die Farben), v von oben nach unten in den Buchstaben, diag schräg, letters am Text befestigt (jeder Buchstabe nimmt seine Farbe mit); per: so lange wandert der Verlauf einmal durch die Schrift (beat, half, bar oder Beats), ohne per steht er still. Gilt für words und scroll, auch mit over: true.
Auf die SCROLLMATRIX passen 9 Zeichen pro Wort; ist ein Wort länger, läuft der ganze Text als Lauftext (der Generator weist darauf hin). Nur ASCII, also ae statt ä. Geht auch im tail. Nicht zusammen mit devices für die Matrix.
text: {words: "FUN", over: true} – der Text liegt über der Szene, die Matrix spielt sie darunter weiter. Mit over: true gelten auch die Schlüssel, die nur die Ebene steuern (siehe overlay), z. B. text: {words: "FUN", over: true, under: 40} – Szene auf 40 % gedimmt, Text voll hell.
Geht auch zusammen mit overlay: Der Text liegt dann in einer eigenen Text-Ebene über Szene und Overlay, und under dimmt beides. Im overlay darf auf der Matrix dann kein Text laufen.
overlayEin zweiter Effekt läuft als Ebene über dem Effekt des Parts, z. B. Glitzern über einer ruhigen Fläche:
overlay: SCENE_SPARKLE – eine Szene, voll aufaddiert.
overlay: {scene: SCENE_SPARKLE, amount: 40} – amount: Stärke der Ebene in Prozent.
overlay: {fx: "progStrobo(${dur}, ${next}, ${beat}, CRGB::White)", mode: mask} – statt einer Szene ein Effektaufruf wie bei fx.
mode: add (Standard: aufaddieren, Schwarz ist durchsichtig), max (der hellere Pixel gewinnt), over (die Ebene deckt, wo sie nicht schwarz ist), mask (die Ebene ist ein Fenster: wo sie dunkel ist, wird der Effekt darunter dunkel), cut (umgekehrt: wo die Ebene hell ist, wird der Effekt darunter dunkel).
span: [50, 100] – die Ebene wirkt nur in diesem Abschnitt jedes Geräts (Prozent wie beim Modifikator span).
devices: {matrix: SCENE_RAIN, guitar: "…"} – andere Ebene je Gerät (Schlüssel wie bei devices); ohne scene/fx läuft die Ebene nur auf den genannten Geräten.
Nur die Ebene steuern, der Effekt darunter bleibt, wie er ist (Längen in Beats, Stärken in Prozent):
pulse: 80 oder pulse: {depth: 80, per: bar} – nur die Ebene pumpt im Beat, z. B. pumpendes Glitzern über ruhiger Fläche.
gate: 2 oder gate: {per_beat: 2, duty: 30} – nur die Ebene blitzt im Raster.
fade_in: 8 / fade_out: 4 – die Ebene baut sich auf bzw. klingt ab.
from: 8 / to: 12 – die Ebene ist nur in diesem Zeitfenster des Parts zu sehen (Beats ab Part-Beginn; ohne to bis zum Part-Ende). fade_in/fade_out beziehen sich auf das Fenster.
under: 40 – der Effekt darunter leuchtet nur mit 40 %, solange die Ebene da ist; die Ebene bleibt voll hell. Folgt Zeitfenster und Ein-/Ausblenden, nicht Puls und Tor.
outline: true – schwarzer Rand von einer LED um alles, was die Ebene zeichnet (nur auf der Matrix). Gedacht für Text: text: {words: "ME", color: rot, over: true, outline: true} – die Buchstaben bleiben auch auf hellem Bild oder auf einem Blinder lesbar. Der Rand blendet mit dem Text aus.
Oben und unten müssen verschiedene Effekte laufen (der Generator prüft das). Es gibt eine Ebene pro Part; der erste Part und der Part, in den die Matrix nach dem Titel-Lauftext mittendrin einsteigt, haben keine. Übergang und Modifikatoren auf Abschnittsebene (pulse, gate, dim …) wirken auf das gemischte Bild.
transitionSo kommt der Part aus dem Bild des vorigen: transition: fade oder transition: {type: wipe, beats: 2}. Ohne beats dauert der Übergang einen Beat.
Typen: cut (harter Schnitt, Standard), fade (Kreuzblende), black (über Schwarz), flash (weißer Blitz auf der Grenze, klingt ins neue Bild ab), wipe / wipe_back (eine Kante läuft über jedes Gerät: Lampe von unten, Gitarre vom Korpus zum Kopf, Matrix von links, bzw. umgekehrt), stage_lr / stage_rl / stage_out (die Geräte wechseln nacheinander über die Bühne: nach rechts, nach links, von der Mitte nach außen), dissolve (Pixel kippen einzeln um).
fade_in, fade_outHelligkeit, nicht Farbe (die Farbwanderung ist fade): fade_in: 4 steigt über die ersten 4 Beats von Schwarz an, fade_out: 8 fällt in den letzten 8 Beats auf Schwarz. Hat der Part einen tail, endet fade_out vor dem Tail; soll das Ende des ganzen Abschnitts ausblenden, gehört fade_out in den tail.
pulseHelligkeit pumpt im Beat: voll auf dem Schlag, danach fällt sie ab. pulse: 50 = Tiefe 50 %. pulse: {depth: 80, per: bar} – per: beat (Standard), half (2 Beats), bar oder eine ganze Zahl in Beats.
Text über BlinderText liegt immer über allem. Hat ein Part einen Text mit over: true und einen Blinder, liegen die Blinder auf der Matrix von selbst unter dem Text: ein heller Hintergrund, auf dem der Text steht. Die anderen Geräte blenden wie immer. Dafür ist nichts einzutragen (blinder_under_text: true aus älteren Shows bleibt gültig). Für die Lesbarkeit outline: true im text: dazunehmen und den Blinder schwach und kurz halten (z. B. amount: 50, len: 0.7).
gateStrobo-Tor über dem laufenden Effekt: gate: 2 schaltet 2-mal pro Beat an und aus. Langsamer als der Beat: gate: {per: 2} – ein Schritt dauert 2 Beats (eine Viertel an, eine Viertel aus). gate: {per_beat: 4, duty: 30} – duty ist der Hell-Anteil in Prozent (Standard 50).
dimDer ganze Part läuft dunkler: dim: 60 = 60 % Helligkeit.
tintZieht das Bild zu einer Farbe hin: tint: rot (50 %) oder tint: {color: blau, amount: 40}. Farben wie bei text. Bei 100 % ist das Bild einfarbig.
onlyNur diese Geräte leuchten voll, der Rest ist aus: only: [guitar, LAMPE1]. Mit only: {devices: [guitar], others: 15} bleibt der Rest auf 15 %. Schlüssel wie bei devices.
spanNur ein Abschnitt jedes Geräts leuchtet, in Prozent entlang des Geräts (Lampe von unten, Gitarre vom Korpus zum Kopf, Matrix von links): span: [0, 50] = untere Hälfte.
softWeiche Farbwechsel, für SCENE_COLORS, SCENE_COLORS_WAVE und den Stern (SCENE_STAR, progStern, progSternNeu): soft: 30 – die Farbe steht und blendet im letzten Drittel des Farbschritts in die nächste; soft: 100 – sie fließt durchgehend von Farbe zu Farbe. Ohne soft springt die Farbe hart wie bisher. Bei anderen Szenen meldet der Generator einen Fehler.
smoothNachleuchten für jeden Effekt, Länge in Beats: smooth: 0.5 – ein harter Wechsel ist nach einem halben Beat vollzogen, aus dem Sprung wird eine Blende. Passt zu alten Effekten mit harten Farbwechseln (progFullColors, progSternNeu). Je länger, desto mehr verschwimmt der Beat; über einem Beat ist kaum noch ein Wechsel zu erkennen. Wirkt nicht auf overlay und text.
blinderHelles Aufblenden wie bei einem Bühnen-Blinder, über dem laufenden Effekt; danach kommt der Effekt wieder hervor. Der Blinder nutzt die volle Leuchtkraft der LEDs (er hebt kurz die Gesamthelligkeit auf 100 %, der Effekt darunter bleibt gleich hell) und in der ersten Hälfte seiner Länge voll hell. Auf allen Geräten wirkt er ab 2 Beats Länge, am stärksten über dunklen oder ruhigen Effekten; nur auf den Lampen und kurz eignet er sich für Rhythmisches.
blinder: bar – auf jede 1 ein Blinder (auch beat, half oder eine Zahl in Beats).
blinder: {at: 8, len: 4} – ein einzelner Blinder 8 Beats nach Part-Beginn, 4 Beats lang (ohne every = einmalig; at: 0 = auf den Einsatz).
blinder: {every: bar, at: 2, len: 1, amount: 80, color: weiss, devices: [LAMPE1, LAMPE2]} – len in Beats (Standard 1), amount in Prozent (Standard 100), color: warm (Standard, wie ein Halogen-Strahler) oder eine Farbe wie bei text, devices: nur diese Geräte blenden (Schlüssel wie bei only). Ein Blinder je Abschnitt.
Die Position (at oder bar) ist immer der Moment, in dem der Blinder voll hell ist. Ohne attack springt er genau dort auf. Mit attack beginnt er von selbst entsprechend früher, damit das Einblenden genau an der Position oben ankommt – auch über eine Part-Grenze hinweg: ein Blinder auf die 1 eines Parts blendet schon am Ende des Parts davor ein (der Generator meldet ihn dort zusätzlich an). Nur vor dem Songbeginn fällt das Einblenden weg.
blinder: {at: 0.5, len: 8, attack: 0.5, hold: 0} – eigener Verlauf: blendet in den attack Beats vor der Position ein (statt aufzuspringen), steht ab der Position hold Beats voll (Standard 0) und klingt über den Rest von len ab (len = ganze Länge einschließlich Einblenden). So entsteht „schnell ein, sehr langsam aus“; attack + hold müssen kürzer sein als len.
blinder: {bar: 63.75, len: 2} – statt at die Taktnummer der Tabelle: das „von takt“ der Zwischenzeile, in der der Wunsch steht. Der Generator rechnet daraus die Beats ab Part-Beginn. An dieser Stelle ist der Blinder voll hell.
blinder: [{bar: 20, len: 2}, {bar: 21.75, len: 1, devices: [LAMPE1, LAMPE2]}] – mehrere Blinder in einem Part als Liste, jeder mit eigenem Zeitpunkt, Verlauf, Farbe und Geräten (höchstens 8 je Part; überlappen sich zwei, zeigt das Gerät den stärkeren).
cuesDie Antwort auf deine Wünsche in den Zwischenzeilen: cues: {21.75: "Blinder auf den Schlag, nur Lampen"}. Schlüssel ist das „von takt“ der Zwischenzeile, der Text landet bei der Generierung in ihrer Spalte „Effekt (füllt KI)“. cues beschreibt nur; den Effekt selbst lösen die anderen Schlüssel des Parts aus (z. B. blinder mit bar). --dry-run listet jeden Wunsch mit seiner Antwort oder „OFFEN“.
whyBegründung, landet als Kommentar im C++-Code.

Übergang und Modifikatoren wirken auf das fertige Bild und lassen sich mit jeder Szene, jedem Effekt und untereinander kombinieren. Längen stehen in Beats, Stärken in Prozent. Sie gelten nur für den Part, in dem sie stehen; ein tail übernimmt sie nicht und kann eigene haben. Auf der Matrix entfällt der Übergang in dem einen Part, in den sie nach dem Titel-Lauftext mittendrin einsteigt; pulse und gate bleiben dort im Beat.

Platzhalter in fx und devices

PlatzhalterWert
${dur}Dauer des Parts in ms
${next}case-Nummer des nächsten Parts
${bpm}Tempo des Parts, gerundet
${beat}, ${half}, ${bar}Dauer eines Beats, zweier Beats und eines Takts in ms

In der Show-Datei stehen keine Takte oder Tempi. Der Generator bricht ab, wenn doch, oder wenn ein Part-Name nicht in der Tabelle vorkommt. So kann die Show nicht unbemerkt von der Struktur abweichen. Setzt du in song.yaml selbst scene, fx, scheme, fade, tail, devices oder text, gilt deine Angabe und nicht die der Show.

Diese Regeln setzt der Generator automatisch um, genau wie in den handgeschriebenen Songs:

Vorspann (Einspieler vor einem Song)

Ein Vorspann ist ein eigener Song-Ordner mit eigener Tabelle und eigener Song-ID (Beispiel: ILoveItIntro_v1, Song 80, führt in „I Love It“, Song 9). Zwei Angaben in den Show-Dateien verbinden die beiden:

WoAngabeWirkung

Reihenfolge beim Generieren: erst den Song, dann den Vorspann. Im ersten Part eines Vorspanns (ohne Titel-Lauftext) dürfen über dem Schwarz Akzente stehen: Blinder, ein Effekt auf einzelnen Geräten und ein tail. Taktnummern gelten dort wie in der Tabelle, das StartBit rechnet der Generator heraus.

Was in der Firmware landet

In der Firmware ist jeder Song, dessen Ordner eine generated.cpp enthält. Tabelle oder show.yaml zu löschen ändert daran nichts, der Code bleibt eingefroren erhalten. Einen Song entfernen: den Ordner (oder nur seine generated.cpp) löschen und danach python tools/songgen.py --assemble ausführen.

So werden die Millisekunden berechnet

  • Dauer eines Beats = 60000 / BPM ms, ein Takt = 4 Beats. Bei 86 BPM: 697,67 ms bzw. 2790,7 ms.
  • Zuerst werden die absoluten Startzeiten aller Parts ab Takt 1 berechnet und erst dann gerundet: Dauer = round(Ende) − round(Start). So entsteht keine Rundungsdrift wie beim Aufaddieren einzelner gerundeter Dauern. Der Abgleich mit dem handgeschriebenen „Dancing On My Own“ ergab 1 ms Abweichung nach 4:25 min.
  • Zeitbasis im Code ist das Start-MIDI: Alle Zeiten werden um das StartBit verschoben (im Code als midi_offset ausgewiesen). Bei 0,125 (1/8 Takt) und 86 BPM ist der erste Part 349 ms kürzer.
  • Die case-Nummern laufen in 5er-Schritten. case 1 und 2 sind für den Lauftext der Scrollmatrix reserviert.
  • Kein Versatz zum Klick über den Song: Ein Gerät bemerkt eine Part-Grenze erst einige Millisekunden später (ein Schleifendurchlauf mit FastLED.show()). Früher ging diese Verspätung bei jedem Wechsel verloren und summierte sich über viele Parts, deshalb wurden Parts in den alten Songs von Hand verkürzt. Bei generierten Songs nimmt die Firmware die Verspätung jetzt in den nächsten Part mit (isGeneratedSong(), wird vom Generator gepflegt). Parts also nie mehr künstlich verkürzen, die Taktzahlen aus dem DAW gelten exakt. Die alten handgeschriebenen Songs laufen unverändert.
  • Die Beat-Effekte (Blitze auf die Viertel, PingPong, Lampen-Puls) rechnen den Beat exakt aus dem BPM, nicht aus einer auf ganze Millisekunden gerundeten Beat-Länge.

Die Tabelle songs/AllTheThingsSheSaid_v1/quelle/struktur.xlsx hat 30 Parts, so geschnitten, wie die Show sie braucht: Synth-Intro, die Hook „this is not enough“, Build-ups und Strobo-Übergänge als eigene Parts, ein Stopp vor dem letzten Chorus. Aus den Wünschen und der Energie hat Claude in show.yaml drei wiederkehrende Motive gemacht:

10 · Bund-Marker-LEDs

Grundregel: Marker, die du gesetzt oder akzeptiert hast, werden nie mehr verändert. Das gilt für jedes Werkzeug und für Claude. Vorgeschlagen wird nur für Songs, die noch gar keine Marker haben.

Wie der Vorschlag entsteht

  • Grundtöne aller Akkorde im Song, so wie sie klingen (Spalte „Akkorde“ der Tabelle oder deine Angabe im Chat).
  • Jeder Grundton wird auf der E-Saite und auf der A-Saite markiert. Beide Saiten teilen sich eine LED pro Bund: ESaite_C und ASaite_F sind dieselbe LED am 8. Bund.
  • Keine Marker auf dem 5. und 12. Bund (dort leuchten immer die blauen LEDs) und keine auf der Leersaite.
  • Höchstens 7 Marker (markerLED1…7). Bei mehr fallen die seltensten Akkorde weg, mit Hinweis.
  • Das Mapping auf die LEDs von Gitarre und Bass passiert wie bisher über die Defines in definitions.h.

Wo die Marker stehen

FallVerhalten
Song-ID hat einen case in src/markerLEDs.cppDeine Handarbeit gilt immer. Claude schlägt nichts vor, der Generator erzeugt keine Grund-Marker. Marker-Listen in show.yaml werden dann ignoriert, Slot-Angaben für einzelne Parts gelten trotzdem. Das betrifft z. B. #31 ATTSS.
Neuer Song ohne MarkerClaude zeigt dir einen Vorschlag und trägt ihn erst nach deinem OK als markers: in show.yaml ein. Danach gilt er als deiner.
show.yaml hat schon markers:Der Block bleibt, wie er ist; der Generator setzt ihn nur um.
markers:
  all: [ESaite_F, ASaite_C, ASaite_E, ASaite_F]   # Gitarre und Bass
  bass: [ESaite_F, ESaite_G]                     # nur Bass (ersetzt all)
  parts:                                        # Spezial-Marker für einzelne Abschnitte
    solo: {bass: [ESaite_Cis, ESaite_Dis]}       # gilt im Abschnitt inkl. seines Tails

Einzelne Marker in einzelnen Parts (Slot-Angabe)

Soll in einem Part nur ein zusätzlicher Marker an- oder ausgehen, schreibst du statt einer Liste {Slot: Marker}. Der Slot ist die Nummer von markerLED1…7, 0 als Marker schaltet den Slot aus.

markers:
  parts:
    chorus 2 hit: {bass: {5: ASaite_E}}     # markerLED5 nur beim Bass, nur in diesem Part
    bridge 1:     {bass: {5: ASaite_E}}
  • Das funktioniert auch bei Songs mit handgeschriebenen Grund-Markern in markerLEDs.cpp. So werden die Marker übernommen, die ein alter Song mitten im Code gesetzt hat.
  • Der Generator schreibt daraus Code an den Anfang der Song-Funktion. Er läuft in jedem Durchlauf nach setMarkerLEDs(), genau wie früher die Zeilen im handgeschriebenen Song.
  • Außerhalb der genannten Parts gelten wieder die Grund-Marker. Belegen die Grund-Marker den Slot nicht, wird er dort ausgeschaltet.
  • Schlüssel wie bei den Listen: all, guitar, bass. Ein Part mit tail schließt den Tail ein.

Der Generator erzeugt aus den Listen setGeneratedMarkerLEDs() in songs_generated.cpp. Aufgerufen wird sie im default-Zweig von setMarkerLEDs(), also nur, wenn es keinen handgeschriebenen case gibt. Ungültige Marker-Namen, mehr als 7 Marker oder unbekannte Abschnitte meldet er als Fehler.

Wie der Schutz abgesichert ist

  • In den Werkzeugen (tools/markers.py): Ein handgeschriebener case in setMarkerLEDs() hat immer Vorrang vor Marker-Listen aus show.yaml.
  • Bei Claude: Die Regel „nie ändern, was gesetzt oder akzeptiert ist“ steht im Memory und im Skill new-song. Fällt Claude etwas auf, etwa ein fehlender Akkord-Grundton, gibt es nur einen Hinweis im Chat, keine Änderung.

Änderungen am bestehenden Code

In src/markerLEDs.cpp sind genau zwei Dinge dazugekommen. Die handgeschriebenen cases sind unverändert.

#include "songs_generated.h"	// setGeneratedMarkerLEDs()
…
		default://defaultLoop();
			// kein handgeschriebener case -> Marker der generierten Songs (show.yaml, sonst nichts)
			setGeneratedMarkerLEDs(songID, partID);
			break;

Vorher stand im default-Zweig nur „DO NOTHING“. Für Songs ohne handgeschriebenen case und ohne markers: in show.yaml bleibt es dabei: Die generierte Funktion setzt dann nichts.

Im generierten Code werden bei jedem Aufruf alle 7 Marker gesetzt, unbenutzte auf 0. So bleiben beim Wechsel in einen Part mit Spezial-Markern keine alten Marker stehen. Unterschiedliche Marker für Gitarre und Bass landen in #ifdef GIT … #else … #endif.
